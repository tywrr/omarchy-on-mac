# macOS app hotkeys and automation tools, researched 2026-10-14

## Scope and evidence

Research for replacing parts of the user's BetterTouchTool `omarchy-on-mac-corporate` preset: app launch/focus hotkeys, Fn/Globe as Super with additional Shift/Control/Option layers, native Mission Control Spaces, moving/resizing windows, and a script-based Ghostty/Herdr launch. The parent investigation verified macOS 26.7.1 and existing Raycast, Vorssaint, OmniWM and BetterTouchTool applications. Product features below are **documented capabilities**, not actions exercised on this Mac. Existing installation does not establish corporate approval.

Sources were retrieved from official product sites, developer repositories, release notes and Apple App Store pages. Search results were used for discovery; comparisons published by competing vendors were not treated as proof about their competitors. Current documentation sometimes describes a newer release than the installed application. In particular, the parent found Raycast 2.4.1 installed while 2.8 is current today; Fn support is documented in the live manual but not tested on 2.4.1.

## Highest-value findings

1. **Raycast already installed is the lowest-friction app-launch and window-sizing candidate.** Its current manual explicitly lists Fn among modifiers and gives `fnA` and `fnCtrlA` examples. It supports app launch/toggle hotkeys and current macOS previous/next-Space window movement. **Numbered desktop commands in its cross-platform manual are Windows-only**, including Move to Desktop 1–9. A separate native-Spaces helper remains relevant. [R1][R2][R3]
2. **rcmd has changed substantially from its older Mac App Store app.** Current standalone rcmd advertises native numbered Spaces, moving a window to a numbered Space, app launch/focus, and saved layouts called Stages. Version 3.0 explicitly introduced **Fn and Caps Lock trigger keys**. Current 3.6.4 adds zsh/AppleScript stage actions, useful for launching a terminal command. It is a real contender rather than just an app-letter switcher. Its arbitrary Fn+Shift/Control/Option chord assignment is not established, and 3.5.4 requires Screen Recording for its current switcher. [C1][C2]
3. **Tuna is the newer successor to Leader Key, from the same developer.** The current Leader Key README tells readers the developer's focus has moved to Tuna. Tuna includes direct command hotkeys, hierarchical Combo Mode, window commands and local scripts. Its site links a creator demo on YouTube. It is promising if changing the interaction model is acceptable; an exact Fn-layer/native numbered-Space replacement is not yet proven. [T1][T2][T3][L1]
4. **SpaceLauncher is actively evolving, not just an old utility.** Its first-party homepage lists 3.5.7 released October 9, 2026. Hold-Space sequences are the default, but it now supports other leader keys and activation styles. App launch arguments, menu commands, simulated keystrokes and AppleScript can cover many existing actions. Native numbered-Space movement is not a documented built-in action. [S1]
5. **Vorssaint is especially recent and already installed.** Its latest stable release is 3.4.1 on October 8, 2026. The subsequent source-level follow-up established that it already ships dedicated app hotkeys, direct executable-script hotkeys, 64 command-row bindings and extensive window-placement hotkeys. Fn is explicitly excluded from its shortcut model and Super-source enum; numbered native desktop actions remain requested. Several relevant bundled modules are currently uninstalled inside the user's app. This corrects the initial README-only omission of its app-hotkey capabilities. See the [source-pinned deep dive](2026-10-14-vorssaint-deep-dive.md). [V1][V2]

## Exact keyboard and Spaces traps

- **Hyper is not automatically equivalent to this preset's Fn-based Super.** Hyperkey/Superkey's default is all four modifiers. The user's Fn+Shift, Fn+Control and Fn+Option layers would not remain distinct if Fn simply became that all-modifier Hyper. Tuna now supports a three-modifier Hyper with extra Shift, but Control and Option are still consumed. Raycast's explicitly documented native Fn+Control combinations and skhd.zig's `fn` modifier deserve more weight than generic Hyper marketing. [Y1][Y2][T3][R1][K1]
- **Native Spaces are different from a saved workspace.** rcmd Stages save a collection of apps/windows but can be restored into native Mission Control Spaces; rcmd also separately advertises actual numbered-Space navigation and sends. Tuna Combo groups are command collections, not new virtual desktops. Window sizing on a display alone does not prove window movement to another desktop. [C1][T2]
- **Raycast manual platform badges matter.** Its `Move to Previous/Next Space` item has a macOS badge. `Open Desktop 1…9`, `Rename Desktop 1…9`, and `Move to Desktop 1…9` have Windows badges. Plain-text extraction removes those badges; inspecting the HTML establishes the distinction. [R3]
- **rcmd older homepage versus live release notes:** 3.6 removed right-Option-letter window jumping in favor of double-tap/hold app trigger and fuzzy window search. Stage trigger defaults changed from Caps Lock to right Option. Latest 3.6.4 supports scripts in Stage items. Avoid promises based on older App Store reviews or Hammerspoon helpers, which 3.0 explicitly removed as a requirement for window jumping. [C2]
- **Permissions are actual adoption gates, not a reason to conclude an app cannot work.** Accessibility is typical. rcmd's current Screen Recording requirement and optional skhd.zig root/DriverKit tap-hold installation deserve particular attention. None of this research established company approval or changed installed permissions/configuration.

## Practical trial order

1. Verify current **Raycast** can record representative Fn chords (Fn+Return, Fn+Shift+Return, Fn+Control+Return, Fn+Option+F) and run app/sizing/script actions; it already exists on this Mac.
2. Evaluate **rcmd** for Fn-triggered app launching plus actual desktop-number send/switch, then assess whether its fixed command grammar supports the user's extra layers. Trial its current Screen Recording/Automation prompts and native Space behavior before declaring it a replacement.
3. If sequences are appealing, look at **Tuna** first and **SpaceLauncher** second. Tuna's creator demo is a plausible match for the remembered recent YouTube launcher video.
4. Use a small native-Spaces helper (the parent agent is researching WhichSpace and other helpers) if the chosen app launcher cannot send to Desktop 1–4 directly. Treat skhd.zig/Hammerspoon as configurable technical alternatives rather than zero-maintenance GUI substitutes.

## Research limits

No app was installed, no shortcut was modified, and no app's hotkey behavior was exercised. No universal guarantee of macOS 26.7.1 behavior follows from features advertised on a site. First-party changelog pages without dates are reported as undated instead of inventing a launch date. After discovery queries, anonymous Tavily search hit an authentication requirement; official pages were fetched directly rather than asking the user to create an account. Context7 was used for current Hammerspoon API details, library resolution followed by two distinct docs queries, within the user's three-command limit.
