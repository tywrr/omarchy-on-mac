# Native window management and Spaces utilities researched 14 October 2026

Scope: current tools that could supply the window sizing, positioning, keyboard shortcuts, or Mission Control desktop parts of an Omarchy-inspired macOS setup. Research is based on author product pages, repositories, release notes, and Apple documentation. No apps were installed and no configuration was changed. The parent investigation verified the target Mac is on macOS 26.7.1. This report does not establish employer software approval or run-time behavior on that Mac.

## Main findings

1. **mimi is the most interesting genuinely new tool for this specific preference.** Its first changelog release is 1 June 2026; its latest tagged release is v0.21.0 on 10 October 2026. It explicitly keeps native Mission Control Spaces, switches numbered desktops, moves a window to another numbered Space without disabling SIP, and supplies manual resizing/focusing commands. It is explicitly beta, its release app is ad-hoc signed and not notarized, it requires a separate hotkey runner, and its native-Space movement uses private Apple APIs. Tiling and the daemon are optional. This is a plausible companion to the already installed Raycast rather than a requirement to adopt automatic tiling. [Repository](https://github.com/y3owk1n/mimi), [tagged release](https://github.com/y3owk1n/mimi/releases/tag/v0.21.0), [history](https://github.com/y3owk1n/mimi/blob/main/CHANGELOG.md).
2. **WindowKeys is the closest match for custom hotkeys driving Apple's own native window tiling.** It is free and invokes the app's system Window-menu commands instead of advertising an alternative desktop system. Current listed release is 3.0.1, 25 June 2025. It does not advertise app launching or sending windows to numbered Mission Control desktops. [Product](https://www.apptorium.com/windowkeys), [releases](https://www.apptorium.com/windowkeys/release-notes).
3. **Loop has an important 2026 development that changes older comparisons.** Stable 1.4.2 is dated 26 January 2026. A rolling prerelease includes native-Space window moves, merged 2 July 2026, including direct numbered-desktop actions. It uses private SkyLight bridged operations. Do not present that feature as available in the last stable release. [Stable release](https://github.com/mrkai77/Loop/releases/tag/1.4.2), [rolling prerelease](https://github.com/mrkai77/Loop/releases/tag/prerelease), [feature PR](https://github.com/mrkai77/Loop/pull/1114).
4. **BentoBox and MacsyZones are newer Space-aware zone tools, but Space-aware does not mean moving windows between Spaces.** They remember different zone layouts for each native Space/display. Their official descriptions do not establish direct send-window-to-desktop shortcuts. [BentoBox](https://bentoboxapp.com), [MacsyZones](https://macsyzones.com).
5. **Moom is an older product with meaningful recent improvements.** Version 4.2 added launch-apps-as-part-of-a-layout in May 2025; 4.6 arrived August 2026. It can supply launch-and-arrange workflows, but its documented action list does not offer moving windows to numbered native Spaces. [Product](https://manytricks.com/moom/), [release notes](https://manytricks.com/moom/releasenotes/), [action documentation](https://manytricks.com/moom/help/).

## Capability comparison

“Not documented” means the reviewed first-party pages did not establish the capability, not that exhaustive source inspection disproved it. A **display** is a physical monitor; a **Space** is a Mission Control desktop. “Workspace layout” is often just remembered window positions and must not be interpreted as an Apple desktop.

## Corporate-Mac installation and security facts

Compatibility with macOS does not prove employer approval. Conversely, requiring Accessibility does not imply requiring admin, a kernel extension, or disabling SIP. These categories should be separated.

- **mimi:** author explicitly states only Accessibility is required, SIP remains enabled, and it loads no scripting addition into the Dock. MacOS14+ is supported. Prebuilt zips are available for Apple Silicon and Intel. Tagged installation docs say the zip app bundle is signed with hardened-runtime entitlements, but later explicitly say the release app is **ad-hoc signed and not notarized** and can be quarantined by macOS. Signing is not the same as a Developer ID/notarized release; this is a material corporate-installation caveat. GitHub build provenance attestations verify the repository/build workflow, **not** Apple notarization. Cross-Space operations use private SkyLight calls and can break after OS updates. [README](https://github.com/y3owk1n/mimi), [version-pinned installation guide](https://github.com/y3owk1n/mimi/blob/v0.21.0/docs/INSTALLATION.md).
- **WindowKeys:** macOS15.1+; native Window-menu operations require the target app to expose Apple's tiling menu items. The product says no user data is collected. The reviewed marketing/release pages do not specify the exact TCC permission prompt or establish notarization, so those remain unverified. It does not advertise a privileged driver/SIP change. [FAQ on product page](https://www.apptorium.com/windowkeys).
- **Loop:** source/release notes establish Accessibility use. Historical 1.0 notes removed the screen-recording requirement for window animations; wallpaper accent-color capture has a separate screen-recording-related history. Do not infer every feature requires Screen Recording. Rolling prerelease says “Use privileged updater helper if needed”; that is updater behavior, not proof of an always-required elevated window engine. The new Space-move implementation uses private bridged SkyLight calls, not the old slow Accessibility-drag simulation. The PR does not require a scripting addition or SIP disable, but an actual installation/policy assessment was not performed. [1.0 release](https://github.com/mrkai77/Loop/releases/tag/1.0.0), [1.1.1 notes](https://github.com/mrkai77/Loop/releases/tag/1.1.1), [rolling release](https://github.com/mrkai77/Loop/releases/tag/prerelease), [Space-move PR](https://github.com/mrkai77/Loop/pull/1114).
- **Moom:** official getting-started guide requires Accessibility. Direct-download Moom4 supports macOS10.13+. The reviewed guide does not establish a Screen Recording or SIP-change requirement. [Guide](https://manytricks.com/moom/help/).
- **Wins:** official FAQ says Accessibility and **optional** Screen Recording, no personal/telemetry/crash-report data transmitted, processing on-device. Supports macOS12+. Native-system-tiling use was added in 3.2, March2026. The official site's “system level integration” means a System Settings pane; it should not be described as a kernel/system extension without further evidence. [Product FAQ](https://wins.cool), [changelog](https://wins.cool/changelog).
- **Lasso:** official FAQ says distributed outside App Store because Accessibility/sandbox restrictions would prevent the full feature set; macOS13+. Exact current price/latest release could not be resolved from dynamically rendered pricing/changelog. It offers a 7-day trial and global layout shortcuts, but no direct Space movement/app launches advertised. [Product](https://thelasso.app), [FAQ](https://thelasso.app/faq), [pricing](https://thelasso.app/pricing), [changelog](https://thelasso.app/changelog).
- **Swish:** official FAQ references Accessibility permission and says low-level operations prevent sandboxing/App Store distribution. MacOS12+, Intel/Apple Silicon. Its keyboard support applies to its snapping/screen/Space gestures, not a general-purpose app-launch shortcut library. [Product and FAQ](https://highlyopinionated.co/swish).
- **MacsyZones:** official FAQ requires Accessibility. It offers manual download and Homebrew; exact notarization/Input Monitoring requirements not verified. Its permission troubleshooting includes an elevated reset command, which does not establish that normal operation needs admin. No such reset was run. [Product](https://macsyzones.com), [repository](https://github.com/rohanrhu/MacsyZones).
- **BentoBox:** macOS14+; direct download/Homebrew, 2-Mac lifetime license. Exact TCC/notarization requirements not established from product/release pages. Per-Space zone memory should not be turned into a claim of direct Space switching/moving. [Product](https://bentoboxapp.com), [releases](https://bentoboxapp.com/releases).
- **Rectangle:** Accessibility is a core implementation mechanism; established free/open-source app. Pro is a direct-download application. Neither the product pages nor the reviewed action docs establish SIP changes or native-Space moving. [Repository](https://github.com/rxhanson/Rectangle), [Pro product](https://rectangleapp.com/pro), [Pro docs](https://rectangleapp.com/pro/docs/getting-started/).
- **Magnet:** available through Mac App Store; Accessibility required as its FAQ troubleshooting confirms. Store distribution does not establish employer approval. [Store](https://apps.apple.com/us/app/magnet/id441258766), [FAQ](https://magnet.crowdcafe.com/faq.html).
- **Swift Shift:** source README establishes Accessibility use and a release procedure that notarizes/staples builds. That is evidence of the intended release process, not a downloaded-binary verification. No driver/SIP modification advertised. [Repository](https://github.com/pablopunk/SwiftShift), [latest release](https://github.com/pablopunk/SwiftShift/releases/tag/1.5.0).
- **1Piece:** author explicitly says **not notarized**, supports through macOS15, has **not been tested on macOS26 or later**, and needs Accessibility. Screen Recording enables thumbnails/previews; those are absent without it. Release recency does not remove these limitations. [Download/install/release page](https://app1piece.com/download/).
- **WinMux:** author explicitly says signed with Apple Development certificate but **not notarized**. The README includes quarantine-removal instructions. No bypass was executed or recommended here. Uses alternative workspaces, making it a weaker fit regardless. [Repository](https://github.com/zimengxiong/winmux).

## What Apple already provides

Apple's native Spaces can be switched with Control+Left/Right, trackpad gestures, or Mission Control. Apps can be assigned to a desktop using Dock > Options. Apple's documentation describes moving a window to another Space by dragging it or by holding it and moving it to the screen edge; it does not provide a default direct send-to-desktop-number keyboard shortcut. This is the capability that needs special attention when replacing the existing BTT Fn+Shift+1–4 bindings. [Apple Spaces guide](https://support.apple.com/guide/mac-help/work-in-multiple-spaces-mh14112/mac).

Native tiling includes Fn+Control+F to fill, Fn+Control+Left/Right for left/right halves, Fn+Control+Up/Down for top/bottom halves, and multi-window arrange variants. Some quarter/corner actions have no default shortcut. Apple's native tiling UI and shortcuts act on normal windows; fill is distinct from creating a full-screen Space. [Apple tiling shortcuts](https://support.apple.com/guide/mac-help/mchl9674d0b0/mac).

The likely architecture is therefore **one hotkey/app-launch tool + Apple's native tiling or one snapping tool + a native-Space movement utility**. Most tools in this report replace only the window-management portion of BTT. Preserving Fn/Globe as the trigger across all components needs a separate capability check; support for “custom shortcuts” alone is insufficient evidence of Fn-modifier support.

## Practical shortlist

- **Least change:** existing Raycast for app hotkeys, WindowKeys for custom native tiling hotkeys, native Mission Control navigation. This does not fully cover sending windows to numbered Spaces unless another component supplies it.
- **Most promising new research candidate:** existing Raycast plus **mimi**, with optional tiling turned off. It directly matches numbered native desktops/window sends; its beta, private-API and unnotarized-release status makes it an experimental candidate rather than the easiest corporate installation. Verify the permitted installation route before a reversible trial; do not assume quarantine bypass is acceptable.
- **Most interesting upcoming GUI candidate:** **Loop rolling prerelease**, because its newly merged native-Space move action could cover the biggest remaining gap. Prefer waiting for a tagged stable release if reliability matters more than immediate exploration.
- **More sophisticated arrangement:** **Moom4** if launching/restoring groups of apps is useful; **BentoBox/MacsyZones** if per-Space custom zones are useful. Pair with a launcher and native-Space utility as needed.
- **Windows-style convenience:** **Wins** if enhanced Mission Control, Dock previews, or Cmd-Tab matter, but it is not proven to cover direct Space sends.
- **Low-priority for this target:** 1Piece despite its 10 October update, because unnotarized/macOS26-unverified is a concrete mismatch; WinMux because replacement workspaces and unnotarized builds are a mismatch.
