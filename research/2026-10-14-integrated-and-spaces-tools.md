# Recent macOS hotkey, workspace and tiling tools

Research snapshot: **2026-10-14**. This branch of the research prioritizes real Mission Control desktops, app launch hotkeys, and moving/resizing windows. It distinguishes downloadable releases from current development source. Nothing was installed, launched, or reconfigured. macOS 26.7.1 was verified by the parent researcher; this agent read the already-installed `/Applications/OmniWM.app` Info.plist: **0.7.6, build 88**, bundle identifier `com.barut.OmniWM`.

The user's **MangoWM/MangoWC** recollection is a Linux tool: the official README calls it **Mango Wayland Compositor**, based on dwl and wlroots, and documents Arch Linux plus Fedora/Gentoo/Guix/NixOS/openSUSE and other Linux distributions. The old `DreamMaoMao/mangowc` URL leads to the current **mangowm/mango** project. It is a Linux desktop compositor rather than a macOS Mission Control hotkey utility; no native macOS edition is documented. [Current official repository](https://github.com/mangowm/mango), [official installation guide](https://mangowm.github.io/docs/installation).

## Strongest fit: preserve native Spaces

**WhichSpace has become substantially more capable than its old reputation as a desktop-number indicator.** Stable **v1.4.1 was released October 13, 2026**. The release-tag README documents numbered native Space switching, global hotkeys, front-window **Send** (stay on current desktop) and **Move** (follow the window), native Shortcuts actions, AppleScript, and URL actions. Window movement is supported on **Sonoma or Tahoe 26.4+**, explicitly unsupported on Sequoia. Therefore this Mac's verified 26.7.1 meets the documented version requirement. It is free MIT software; it does not launch apps or resize windows itself. [Stable release](https://github.com/gechr/WhichSpace/releases/tag/v1.4.1), [release-tag documentation](https://github.com/gechr/WhichSpace/blob/v1.4.1/README.md#keybinds), [movement compatibility](https://github.com/gechr/WhichSpace/blob/v1.4.1/README.md#moving-windows), [MIT license](https://github.com/gechr/WhichSpace/blob/v1.4.1/LICENSE).

**Verified Fn follow-up:** WhichSpace v1.4.1's recorder deliberately strips Fn, but its stored shortcut model and engine preserve it. Directly setting the five saved Move bindings to Carbon modifiers **131584** (Fn+Shift) worked; the user physically confirmed Fn+Shift+2 and Fn+Shift+1 transfer the focused window and follow it. **No external hotkey front end or script is required for these bindings.** See [configuration, backup and verification](2026-10-14-whichspace-fn-move-test.md). [Recorder source](https://github.com/gechr/WhichSpace/blob/v1.4.1/Vendor/KeyboardShortcuts/Sources/KeyboardShortcuts/Shortcut.swift#L61), [Fn modifier conversion](https://github.com/gechr/WhichSpace/blob/v1.4.1/Vendor/KeyboardShortcuts/Sources/KeyboardShortcuts/Utilities.swift#L287).

WhichSpace uses Accessibility for interaction, synthetic Dock swipe events for fast switching, and **private SkyLight APIs** for native window movement. The reviewed source performs the bridged operation in the application's process; no Dock injection installer or SIP change is described. That is different from claiming Apple supports these APIs or guaranteeing future macOS compatibility. Signing/notarization of the downloadable binary was not independently checked. [Space switching implementation](https://github.com/gechr/WhichSpace/blob/v1.4.1/WhichSpace/SpaceSwitcher.swift), [window mover and OS checks](https://github.com/gechr/WhichSpace/blob/v1.4.1/WhichSpace/SpaceWindowMover.swift), [private bridged implementation](https://github.com/gechr/WhichSpace/blob/v1.4.1/WhichSpace/Classes/WindowSpaceMove.c), [Accessibility implementation](https://github.com/gechr/WhichSpace/blob/v1.4.1/WhichSpace/Accessibility.swift).

**Glide by Vatsal057 is a recent BTT-like alternative worth testing.** Its repository was created March 27, 2026 and **v2.4.0 shipped September 24, 2026**. Crucially, the *release-tag* docs confirm global keyboard shortcuts, Open App, left/right halves and corners, maximize/restore, fullscreen, display moves, application menu actions, key sequences, shell commands, AppleScript and macOS Shortcuts. It keeps ordinary native desktops; its action catalog has **no direct move-window-to-numbered-Space action**. Sending OS Space shortcuts or invoking WhichSpace/mimi would need a separate integration. Fn support is unverified: keyboard docs list Command, Option, Control and Shift. [Release](https://github.com/Vatsal057/Glide/releases/tag/v2.4.0), [released action catalog](https://github.com/Vatsal057/Glide/blob/v2.4.0/docs/03-actions.md), [released hotkey guide](https://github.com/Vatsal057/Glide/blob/v2.4.0/docs/04-keyboard-shortcuts.md).

This Glide is free MIT, requires Accessibility, requests Screen Recording only for thumbnails, and Automation for custom scripts/menu commands. Its developer documents private MultitouchSupport and WindowServer techniques. The distributed app's signing/notarization was not established; its installation guide describes Gatekeeper friction. Treat its self-published RAM/CPU comparison to BTT as marketing, not measured evidence. [Release-tag README](https://github.com/Vatsal057/Glide/blob/v2.4.0/README.md).

## Recommended experiments for the parent report

The follow-up source audit changes the first recommendation: **keep preferred Vorssaint** and use its shipping app/script/window hotkeys. See [Vorssaint deep dive](2026-10-14-vorssaint-deep-dive.md). Fn and numbered native-desktop actions remain the gaps; this report's alternatives are useful for those specific roles.

1. Evaluate **Vorssaint + WhichSpace v1.4.1** if supported modifier chords are acceptable. For exact Fn fidelity, retain the relevant BTT bindings or compare **rcmd** (parent agent verified Fn/native Space switch/send) against **existing Raycast + WhichSpace**. Runtime integration remains untested.
2. Compare **Glide by Vatsal057** as a newer open-source BTT-style hotkey/action front end. Test Fn recognition before migration and use a separate native desktop mover if needed.
3. Consider **Space Rabbit / InstantSpaceSwitcher** only if animation delay is the remaining pain. They are adjuncts, not full replacements.
4. If the user wants optional automatic tiling *on existing desktops*, investigate **glide-wm**, **Paneru**, **Amethyst** and **PaperWM.spoon** before managers with their own desktop layer.
5. Existing OmniWM can be evaluated without installation, but its documented workspace model is a real preference tradeoff, not a transparent BTT swap.

Corporate suitability is a technical assessment, not employer approval. Accessibility and Input Monitoring may be controlled even without MDM enrollment. Private APIs do not automatically imply SIP changes; signed/notarized does not prove corporate approval. No system permissions or app-policy allowlist were changed or conclusively audited.
